# LearnandForge

**Learn the trade. Build the business.** Sinhala‑first, practical courses for Sri Lankan entrepreneurs — textiles & apparel, agriculture & plantation, food, handicrafts, retail, services and business foundations.

The site is a dependency‑free static build (plain HTML/CSS/JS generated by a small Node script), so it deploys to Vercel with zero configuration beyond the included `vercel.json`.

## Run locally

```bash
npm run dev        # builds ./dist and serves it on http://localhost:3000
npm run build      # build only
```

Node 18+ is the only requirement. There are no npm dependencies to install.

## Deploy to Vercel

1. Push this repository to GitHub.
2. In Vercel: **Add New → Project → Import** `kasun-Dave/LearnandForge`.
3. Leave the defaults — `vercel.json` already sets the build command (`npm run build`) and output directory (`dist`). Click **Deploy**.

Every push to `main` redeploys. Update `site.url` in `content/site.json` to your real domain once you have it (it is used for canonical links and the sitemap).

## Project structure

```
content/
  site.json                       ← all categories and courses (the single source of truth)
  courses/<slug>/content.html     ← course reader content (body markup only)
public/
  assets/site.css, site.js        ← platform styles & behaviour (lf- prefixed classes)
  assets/course.css               ← course reader styles, scoped under .course-root
  assets/course-runtime.js        ← self-marking quizzes + progress (saved in the browser only)
  favicon.svg
scripts/
  build.mjs                       ← generates dist/ from content + templates, checks internal links
  templates.mjs                   ← HTML templates for every page type
  serve.mjs                       ← tiny preview server
vercel.json                       ← build command, output dir, clean URLs, caching
```

Generated routes: `/`, `/categories/`, `/categories/<slug>/`, `/courses/`, `/courses/<slug>/`, `/courses/<slug>/learn/`, `/about/`, `404.html`, `sitemap.xml`, `robots.txt`.

## Adding a course

1. Write the course as a self‑contained HTML fragment and save it as `content/courses/<slug>/content.html`. The reader expects this structure (see the first course for a full example):
   - a `.shell` wrapper with a `.masthead` (title, progress bar `#progress-fill` / `#progress-text`),
   - a `<nav class="syllabus">` with `.nav-item[data-key]` links,
   - a `<div class="course-main">` with `<section id="…" class="module">` blocks,
   - quizzes as `<div class="quiz" data-quiz="key">` containing `<fieldset class="q" data-answer="a|b|c|d">` with four radio options and a `<p class="expl" hidden>` explanation.
   The runtime marks quizzes, stores progress under `lf-progress:<slug>` in `localStorage`, and highlights the active module.
2. Add the course to `content/site.json` under `courses` (copy the existing entry; set `category` to an existing category slug and `status` to `"available"`).
3. `npm run build` — the build fails loudly if a slug, category or content file is wrong, or if any internal link is broken.

Planned (not yet written) courses are listed per category under `planned` in `site.json`; they appear as "Planned" cards until a real course replaces them.

## Notes

- Course figures (prices, MOQs, lead times, test targets) are typical ranges as of the course's `updated` date and are marked as such; readers are told to replace them with real quotations.
- Business‑registration, tax and import content is general information, not legal or financial advice.
- The e‑mail capture on the home page is front‑end only (it validates and thanks the visitor). Wire `submitCapture()` in `public/assets/site.js` to your list provider or a Vercel function when you are ready.
